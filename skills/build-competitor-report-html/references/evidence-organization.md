# Screenshot Gallery Organization

Organize screenshots for browsing, not for argument or analysis.

## Choose a simple structure

Use one primary grouping method:

- **By app** when readers need to browse each competitor separately.
- **By journey order** when screenshots form one continuous flow.
- **By page type** only when the user explicitly wants equivalent screens placed together.

Within a group, preserve the known chronological order. Do not invent missing steps, capture order, completeness, or product intent.

## Screenshot selection

Select for journey continuity and completeness, not for a fixed count or a representative sample.

- Preserve one clear image for every substantive node in the approved journey, in actual order. Treat a node as substantive when removing it would make the goal, an important decision, a result, or a transition difficult to understand.
- Consolidate minor variants of the same page and state, such as a checkbox being on or off, a nonessential popup appearing or disappearing, or a small transient visual change. Keep the clearest stable state.
- Keep a modal, selection state, validation state, or error as its own node only when it is a required decision, a blocker, an outcome, or necessary to explain the next transition.
- Combine different scroll positions of the same page and state into one reliable long screenshot when possible. If reliable stitching is unavailable, keep the single viewport that best identifies the node and its transition; prefer the topmost clear view unless another viewport contains the essential decision or outcome.
- Exclude corrupt, unreadable, irrelevant, and exact-duplicate images.

Do not impose a screenshot-count cap or require an exact file set. Two selections may differ while both are valid if each preserves the full journey, avoids unexplained jumps, and removes only low-information same-page variation.

## Labels and descriptions

- Use `App · Page or state` as the default screenshot title.
- Keep captions to a short page/state label.
- Add one factual sentence only when the screenshot cannot be interpreted from its label and surrounding group.
- Do not attach insights, implications, judgments, recommendations, or cross-app comparisons to screenshots.

## Layout

- Let screenshots occupy most of the page.
- Use a uniform viewer grid that wraps naturally.
- Preserve each image's aspect ratio.
- Keep long screenshots internally scrollable through the registered viewer.
- Use a compact collapsed source section only when the main gallery would otherwise repeat screenshot-redundant material.

## Final review

- The grouping and order are easy to follow.
- Every substantive journey node has clear evidence and the sequence has no unexplained jump.
- Adjacent screenshots do not repeat a same-page state without adding a required decision, blocker, outcome, or transition.
- Labels are factual and neutral.
- Partial, blocked, or stopped coverage is noted only where necessary.
